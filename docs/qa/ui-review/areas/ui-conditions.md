Scope: `web/src/app/(app)/conditions/page.tsx`, `web/src/app/(app)/conditions/[id]/page.tsx`,
`web/src/components/conditions/ConditionsList.tsx` (+ `.module.css`),
`web/src/components/conditions/ConditionDetail.tsx` (+ `.module.css`),

## Orphans

1. **Both detail-page "Add evidence" buttons are dead CTAs** — `ConditionDetail.tsx:177` and `:220`: `onClick={() => setStepOpen(false)}`. The page's primary action — the thing the "Strengthen this claim" panel and the next-step modal both tell the veteran to do — performs nothing (main button) or a mislabeled dismiss (modal button). No honest user story can be written for a primary button that no-ops. This is the single worst issue in the area; contrast with the list empty-state CTA which correctly links to `/documents` (`conditions/page.tsx:17`).
2. **`TriadCell.tsx` is dead code** — `components/ui/TriadCell.tsx:10-21` + its module.css are imported by no file in `src/` (grep: only self-reference). Candidate to delete or wire into the desktop table (it would actually fix the legend/color mismatch in A#4 by pairing leg-colored labels with status tags).
3. **Triad key legend's colored dots** — `ConditionsList.tsx:58-68`: the leg-identity colors decorate a legend for a color code that appears nowhere on the page (everything visible is status-colored). The *text* (decoding Dx/IS/Nx) earns its place for mobile; the colors are decoration masquerading as a key.
4. **`StrengthBar`** — `components/ui/StrengthBar.tsx:8-17`: in-scope per the audit list but used only by `HomeHero.tsx`, not in the conditions area; within this area it is unused. (On Home it's also `role="presentation"` with no accessible alternative, and `StrengthBar.module.css:11` hardcodes `rgba(255,255,255,0.22)`.)
5. **`CondVM.fullName`** — `lib/adapters/condition.ts:40` sets `fullName: r.name`; the detail `h1` (`ConditionDetail.tsx:94`) uses a field that is a stub alias. Harmless visually, but it's API surface pretending a distinction exists.
6. **"VASRD —" pill** — `ConditionDetail.tsx:90`: when the code is unknown the hero renders a pill whose content is a dash; an element whose story is "tell the user we know nothing" should not render.

## Missing Affordances

1. **Add evidence from the detail page (broken, not absent-by-design)** — "As a veteran looking at my weakest leg, I want to upload the suggested evidence right now, so that I close the gap while I'm motivated." The button exists but is a stub (Orphans #1); minimum fix is navigating to `/documents`, ideal is an upload sheet pre-tagged to the condition/leg.
2. **Free-tier upgrade path on conditions** — "As a free user, I want to see what condition analysis looks like and a clear upgrade prompt, so that I understand what Pro buys." Conditions are AI-analysis output (paid tier); a 402 from `/claim/conditions` throws (`client.ts:49`) into the generic retry boundary (`error.tsx:13-17`). There is no paywall state, teaser, or upgrade CTA anywhere in this area.
3. **VSO viewer mode** — "As a VSO viewer, I want to open a shared veteran's conditions, so that I can advise them." `serverFetch` supports `X-View-As` (`client.ts:39`), but `loadConditions`/`loadConditionDetail` (`endpoints.ts:104-119`) never accept/forward a `viewAs` — the area is owner-only. (Known parked item per nav-reorg roadmap; recording so it isn't lost.)
4. **Trace evidence items to source documents** — "As a veteran, I want to tap an evidence bullet and see the document it came from, so that I can verify the AI didn't hallucinate." LegCard items are plain strings (`ConditionDetail.tsx:55-62`). For a trust-sensitive educational tool this is the highest-value missing link.
5. **Dispute/dismiss a condition** — "As a veteran, I want to remove or flag a condition the AI got wrong, so that my claim summary reflects reality." No edit/dismiss/feedback affordance on list or detail.
6. **Manually add a condition** — "As a veteran, I want to add a condition I know I have but the AI missed, so that my plan is complete." The only path is uploading more evidence and hoping.
7. **Clear-filter escape hatch + saner default** — "As a veteran with zero ready conditions, I want the list to show my conditions on arrival, so that I don't think they're gone." Default `"ready"` filter (`ConditionsList.tsx:27`) + actionless in-filter empty text (`:71`). Default to `all` (or `ready` only when non-empty) and add a "Show all" button to the filtered-empty state; put filter in the URL.
8. **Not-found recovery** — "As a veteran on a stale link, I want a styled 404 with a 'Back to conditions' button." No `not-found.tsx` in the app (B#31).
9. **Analysis freshness / re-run** — "As a veteran who just uploaded new evidence, I want to know whether these scores reflect it, so that I trust what I'm reading." No analyzed-at timestamp or refresh indicator on list or detail.
10. **Condition context for Ask AI** — "As a Pro user, I want 'Ask AI about this' to actually be about *this*." Button navigates to bare `/ask` with no condition id (`ConditionDetail.tsx:184`).
11. **Sort/search for long lists** (minor) — veterans with 10+ conditions can't sort by rating/readiness or search by name.

## A11y & Consistency

**Accessibility**
- Desktop "table" is a div grid with zero table semantics — no `role="table"/"row"/"columnheader"` (`ConditionsList.tsx:75-116`); screen readers lose the row/column relationships the layout exists to convey.
- TriadDots encode status by color + `title` tooltip only (`TriadDots.tsx:23-27`) — unusable on touch and invisible to SRs; needs visually-hidden status text. This is the *only* triad readout on mobile cards.
- `Chip` filter buttons have no `aria-pressed`/`role="tab"` state (`Chip.tsx:15`) — active filter is conveyed by color only.
- Modal (`Modal.tsx:15-55`): focus moves in on open, Escape works, but no focus trap (Tab walks the background) and no focus restore to the trigger on close.
- "Why this number?" has `aria-expanded` but no `aria-controls`/panel `id` (`ConditionDetail.tsx:109-123`).
- Rating em-dash placeholders (`ConditionsList.tsx:109,140`) have no accessible name ("not yet ratable").
- Chips compute to roughly 35–36px tall (`Chip.module.css` padding 8px + 0.84rem text) — under the 44px tap-target guideline, on a horizontally scrolling mobile strip.
- `RatingBadge` `.sub` at `0.59rem` (`RatingBadge.module.css:33`) is below any readable/contrast-safe minimum.
- `tdName b` ellipsis without `title` — truncated names unrecoverable (`ConditionsList.module.css:109-117`).

**Semantics / honesty**
- RatingBadge is always strong-green regardless of value (`RatingBadge.module.css:11-12`) — low confidence wears a high-confidence costume.
- Backend "moderate" vs "weak" both display "Partial" (`triad.ts:12`) — flattening the user can't see.

**Design tokens**
- Raw rgba literals: `Chip.module.css:35` (`rgba(255,255,255,0.2)`), `RatingBadge.module.css:16` (`rgba(255,255,255,0.14)`), `StrengthBar.module.css:11` (`rgba(255,255,255,0.22)`). The tokens.ts no-hex test (`lib/theme/tokens.ts:3-8`) only polices tokens.ts, not module CSS.
- Pervasive hardcoded px alongside `--s*` spacing tokens: e.g. `ConditionsList.module.css:54` (grid columns), `:57` (`padding: 0 18px`), `:167` (`padding: 15px`); `ConditionDetail.module.css:145,151,190,207,250` (`18px/11px/14px/16px 18px`). Consistent with mockup-port style, but the token layer exists and is bypassed roughly half the time.
- Odd one-off font sizes (`0.90625rem`, `0.78125rem`, `0.71rem`, `0.69rem`, `0.59rem`) suggest px→rem transliteration rather than a type scale.

**State coverage summary**
- Loading: shared skeleton only (Home-shaped); no per-page skeleton. Error: shared generic boundary; 402 not differentiated. Empty: good at page level, weak within filters. Free vs Pro: **entirely unhandled** in this area. Mobile vs desktop: thoroughly handled (parallel table/cards, stacked detail). Dark mode: token-based throughout except the three rgba literals.

## Verdict

The information design is strong: the list and detail pages tell a coherent triad story, every *data* element (status tags, rating, presumptive pill, rationale, weakest-leg callout, next-step bar) maps cleanly to a real veteran story, and mobile/desktop parity is genuinely done. But the area fails its users at exactly the moment of action: **the detail page's primary CTA ("Add evidence") is a no-op stub in both places it appears**, the strengthen-panel and next-step modal funnel users into that dead button, "Ask AI about this" forgets which condition "this" is, and a free user or 402 lands on a retry-forever error with no paywall story. Add the `ready`-default filter that greets needs-work users with an empty screen, and the three first-session paths (new user, free user, returning veteran with weak claims) all hit a wall. Fix order: (1) wire Add evidence to `/documents` (or upload sheet) — one-line fix, page-defining impact; (2) default filter to `all` + URL state; (3) 402-aware error/paywall state; (4) TriadDots accessible status text + table semantics; (5) delete or adopt `TriadCell`; (6) confidence-aware RatingBadge color.
