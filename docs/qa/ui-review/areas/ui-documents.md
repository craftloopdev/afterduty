## Orphans (no honest user story — candidates to cut or fix)

1. **Pro upsell banner + "Upgrade to Pro" pill on upload 402** — `UploadCard.tsx:27-28,67-74`. Backend explicitly made evidence upload free (`IntakeController.java:95-98`); `/claim/evidence` cannot return 402. Dead UI whose copy ("Evidence upload … are a Pro feature") actively contradicts the free-tier promise. Either delete, or repurpose for the real paid gate (extraction deferral) which today is *invisible* (#20).
2. **Green "Processed" badge** — `DocumentsView.tsx:21-24` via `evidence.ts:29`. Condition `status === "complete"` never matches production data (backend writes "processed"). The only place it renders is the dev fixture. As shipped it is decoration that no real user sees.
3. **Dashed dropzone border** — `UploadCard.module.css:7`. The universal visual grammar for "drag files here", with zero drag/drop handlers in `UploadCard.tsx`. Decoration masquerading as function.
4. **"That file is too large." error branch (413)** — `UploadCard.tsx:29-30`. Backend oversize check returns **400** (`IntakeController.java:102-104`), so this string is unreachable through the documented path; oversize users get the generic failure instead.
5. **AddModal's three options sharing one `/documents` redirect** — `AddModal.tsx:21-24`. "Describe what you remember" and "Add a condition" promise chat-extraction and condition-creation flows that don't exist on the destination; even "Upload documents" doesn't open the picker. Stubs wearing finished-feature copy.

## Missing Affordances (stories with no supporting element)

1. **Delete**: As a veteran, I want to remove a document I uploaded by mistake (wrong file, someone else's records) so that my claim file is accurate. Backend already has `DELETE /api/claim/evidence/{evidenceId}` (`IntakeController.java:324`) — no UI.
2. **Download / view original**: As a veteran (or VSO reviewing), I want to open the document I uploaded so that I can confirm it's the right one. Backend has `GET /evidence/{id}/download` (`IntakeController.java:264`) — no UI.
3. **Document detail**: As a Pro user, I want to see what the AI extracted from each document (`aiSummary`, `aiExtractedData` exist on `EvidenceResponse`, `web/src/lib/models/api.ts:128-129`) so that I can verify/correct the facts feeding my conditions. Cards are dead-ends.
4. **Processing failure surfaced + retry**: As a veteran whose document failed extraction (`status="error"`, `PipelineService.java:116-117`), I want to see that it failed and retry, so that my claim isn't silently built on missing evidence. Today "Error" renders as faint gray pending-styled text; `processingMessage` is dropped (`evidence.ts` never maps it; `DocVM` has no field for it).
5. **Usage-cap pause explanation**: As a free user whose doc is `deferred_usage_limit` with message "Paused — plan limit reached. Resumes <date>." (`PipelineService.java:74-76`), I want to see that pause and an upgrade path, so that I understand why nothing is happening. This is the *real* upsell moment — currently rendered as the literal string "Deferred_usage_limit". (The dead 402 banner, #Orphan 1, was aimed at this story.)
6. **Live status updates**: As a veteran who just uploaded, I want the card to move pending → processing → done without manually reloading, so that I trust the pipeline. Page is a server component with a single `router.refresh()` after upload (`UploadCard.tsx:38`); the async pipeline's later transitions never appear.
7. **Multi-file upload and drag-and-drop**: As a veteran with a folder of medical records, I want to drop several files at once so that intake isn't one-click-per-file. Input lacks `multiple` (`UploadCard.tsx:50-55`); no DnD despite the dashed border.
8. **Upload constraints up front**: As a veteran, I want to know accepted types and the 50 MB limit before choosing a file so that I don't hit opaque failures. Accept list is invisible; limit appears nowhere.
9. **Upload date / sort / filter / search**: As a veteran with a long claim history, I want documents ordered and filterable (date, type, status) so that I can find one record. `createdAt` exists (`api.ts:132`) and the backend already orders by it (`IntakeController.java:252`), but it's never shown; no controls exist.
10. **Sign-in recovery on 401**: As a veteran whose session expired mid-upload, I want a "Sign in" link in the error so that I can resume in one tap (`UploadCard.tsx:33-34` is text-only).
11. **VSO viewer mode**: As a VSO with `canUploadDocs` permission (share model `web/src/lib/models/vm.ts:49-51`; backend X-View-As upload billing handled at `IntakeController.java:148-154`), I want to upload/view documents on the veteran's claim from the web. Web shell has no viewer mode at all (known parked item) — documents page has no read-only or on-behalf variant.
12. **Upload progress for large files**: As a veteran on rural DSL uploading a 40 MB C-file PDF, I want a progress indicator so that I don't assume it froze. Only an indeterminate spinner exists (#7).

## A11y & Consistency

**Accessibility**
- **No `:focus-visible` styles anywhere** in `globals.css`, `Button.module.css`, `UploadCard.module.css`, or `DocumentsView.module.css` (grep clean). Browser defaults survive (nothing sets `outline: none`), but the navy-on-navy primary button + default ring should be verified; an explicit token-based focus ring is the fix.
- **Status text contrast**: `.pending` uses `var(--faint)` (`DocumentsView.module.css:53`) for *meaningful* status (including error states) at 0.78rem — high risk of failing WCAG 1.4.3; status is information, not decoration.
- **Tap target**: `.proLink` is ~31px tall (`UploadCard.module.css:59-69`) — under the 44px the project's own Button enforces (`Button.module.css:13`). (Moot if Orphan 1 is deleted.)
- **List semantics**: grid is nested `div`s (`DocumentsView.tsx:7-9`); `ul/li` would announce document count to screen readers.
- **Heading order**: page h1 (TopBar) → EmptyState h3; skip h2 (`EmptyState.tsx:17`).
- **Truncation tooltip**: full filename only via `title` attribute (`DocumentsView.tsx:16`) — inaccessible on touch; consider full name on a detail view (pairs with Missing Affordance 3).
- Positive: `role="alert"` on both banners (`UploadCard.tsx:68,76`); `aria-busy` + disabled on loading Button (`Button.tsx:36`); icons `aria-hidden` by default with adjacent text (`Icon.tsx:46-47`); Modal has proper dialog semantics (`Modal.tsx:37-46`); skeleton has `aria-busy`/`aria-label` (`loading.tsx:6`).

**Design tokens / consistency**
- **No raw hex anywhere** in the audited files — `tokens.ts` discipline holds (enforced by `tokens.test.ts`); `color-mix(in srgb, var 14%, transparent)` in `DocumentsView.tsx:12` stays token-based. Good.
- Raw px spacing violations (project uses `--s*` scale): `EmptyState.module.css:6-7` (`gap: 12px`, `padding: 40px 24px`); `UploadCard.module.css:27` (`gap: 2px`), `:63-65` (`padding: 8px 14px`, `gap: 6px`); `DocumentsView.module.css:48` (`gap: 4px`); `Button.module.css:29` (`border-radius: 11px` raw vs `--r-*`).
- Hardcoded 44px icon-chip size duplicated in `UploadCard.module.css:13-14` and `DocumentsView.module.css:23-24` — candidate for a shared chip primitive (third copy exists in AddModal styles).
- Status-state styling is bespoke here (`.ok`/`.pending`) while the design system has `StatusTag`/`Pill` components — documents should reuse them so error/pending/processed get consistent treatment app-wide.
- Stale comment: `web/src/app/api/upload/route.ts:7-8` documents 402 passthrough as expected upload behavior — out of date with `IntakeController.java:95`.
- Fixture vocabulary drift: `fixtures/documents.ts:5-8` uses `"complete"`/`"extracting"`, which the backend never emits — fixtures should mirror `pending|processing|processed|error|deferred_usage_limit` so dev pages catch adapter bugs like #19.

## Verdict

The happy-path skeleton is solid — clear upload entry, sensible empty state, token-clean styling, decent ARIA on the dynamic bits — but the page fails its core user story the moment real data arrives: **no production document can ever reach the "Processed" state** (`evidence.ts:29` checks "complete"; backend emits "processed"), error and usage-cap states leak raw enums in faint gray with their human-readable `processingMessage` discarded, and the one upsell banner that exists guards a gate the backend removed while the *actual* paid gate (extraction deferral) is invisible. Documents are also write-only: the backend already supports delete, download, and rich extraction detail, yet every card is a dead-end. Priority order: (1) fix the status contract + render `processingMessage` with proper error/paused styling, (2) delete or repurpose the dead 402 banner toward the `deferred_usage_limit` story, (3) add delete/download/detail actions, (4) honest dropzone (DnD + `multiple`) or drop the dashed border, (5) focus-visible ring + status-text contrast.
